# Py.bot — ربات سیگنال SMC با اشتراک Telegram Stars

ربات تلگرام برای ارسال سیگنال فیوچرز بر پایه‌ی Smart Money Concepts و فروش اشتراک با Telegram Stars (⭐).

> ⚠️ این ربات ابزار اطلاعاتی است، نه توصیه مالی. **هیچ سودی تضمین نمی‌شود.** منطق SMC در این پروژه اکتشافی و ساده‌شده است و روی داده‌ی واقعی اثبات نشده؛ قبل از فروش حتماً بک‌تست و فوروارد‌تست کنید.

## قابلیت‌ها
- **شخصی‌سازی:** `/settings` (حداقل امتیاز، فقط خرید/فروش، خاموش‌کردن اعلان TP/SL)، **کد هدیه** (`/promo`، ادمین: `/newpromo`, `/promos`).
- **گزینه‌ی BE:** با `BE_AFTER_TP1=1` بعد از TP1 حد ضرر به ورود می‌رود (اول با `/backtest` مقایسه کنید).
- **منبع داده:** Binance یا Bybit (`EXCHANGE`)؛ آداپتور Bybit فقط با پاسخ ساختگی تست شده.
- **پرداخت امن با Stars:** چند پلن (هفتگی/ماهانه/۳ ماهه)، اعتبارسنجی کامل سفارش (پلن، کاربر، مبلغ، ارز `XTR`)، ثبت پرداخت و تمدید در یک تراکنش اتمیک، جلوگیری از تمدید دوباره با پرداخت تکراری، بازگشت وجه (`/refund`).
- **اشتراک:** تمدید از انقضای فعلی (اگر فعال) یا از اکنون (اگر منقضی)، یادآوری ۲ روز قبل از پایان، پیام پایان اشتراک.
- **سیگنال SMC:** BOS/CHoCH، Order Block، FVG، Liquidity Sweep، فیلتر Premium/Discount، امتیاز ۱ تا ۴، ورود/SL و **TP1 تا TP5**.
- **ردیابی:** اعلام لحظه‌ای هر TP (فقط یک‌بار)، حد ضرر، انقضا، ثبت نتیجه برحسب R. اگر یک کندل هم SL و هم TP را لمس کند، قاعده‌ی محافظه‌کارانه: **SL اول**.
- **رشد درآمد:** تست رایگان یک‌بار (`/trial`)، لینک دعوت با پاداش روز رایگان (`/ref`)، آمار عملکرد شفاف و واقعی (`/performance`)، انتشار نتایج در کانال عمومی (اختیاری)، آمار فروش برای ادمین (`/stats`).
- **ابزار کاربر:** ماشین‌حساب حجم معامله (`/risk`)، سیگنال‌های باز (`/open`)، `/terms`، `/paysupport`.
- **بک‌تست واقعی:** `/backtest` (ادمین) و `backtest.py` روی تاریخچه‌ی واقعی بایننس، با کارمزد، افت سرمایه (drawdown)، ضریب سود و قضاوت آماری صادقانه.
- **گزارش و بکاپ هفتگی:** هر ۷ روز گزارش عملکرد برای مشترکان/کانال و فایل پشتیبان دیتابیس برای ادمین (`/backup` هم دستی).
- **پایداری:** retry با backoff، timeout، اعتبارسنجی داده‌ی بازار، جلوگیری از سیگنال تکراری/کهنه، مدیریت کاربر بلاک‌کننده و `RetryAfter`، حذف توکن از لاگ‌ها.

## استقرار روی Railway
راهنمای کامل قدم‌به‌قدم: **[RAILWAY.md](RAILWAY.md)** (ریجن غیرآمریکایی، Volume برای دیتابیس، متغیرها، تست ۱ ستاره‌ای).

## نیازمندی‌ها
Python 3.10+ (روی 3.12 تست شده)

```bash
pip install -r requirements.txt
cp .env.example .env     # مقادیر را پر کنید (فایل .env را هرگز در Git نگذارید)
set -a; source .env; set -a +a   # یا متغیرها را در داشبورد هاست وارد کنید
python signal_bot.py
```

## خرید با Stars
`/buy` ← انتخاب پلن ← فاکتور `XTR` ← تایید `pre_checkout` ← `successful_payment` ← ثبت اتمیک و فعال‌سازی. هر مرحله دوباره اعتبارسنجی می‌شود. برداشت Stars از بخش ربات در تلگرام/Fragment انجام می‌شود (مقررات و زمان نگه‌داشت را در تلگرام ببینید).

## دیتابیس و مهاجرت
SQLite (`DB_PATH`). هنگام اجرا، مهاجرت خودکار و بی‌خطر انجام می‌شود: فقط جدول/ستون اضافه می‌شود و داده‌ی نسخه‌ی قبلی (`subs`, `payments`, `signals`) حفظ می‌شود (در تست مهاجرت اثبات شده). **روی هاست ابری حتماً دیتابیس را روی Volume دائمی بگذارید، وگرنه با هر دیپلوی پاک می‌شود.** از فایل دیتابیس بکاپ بگیرید.

## بک‌تست روی داده‌ی واقعی (قبل از فروش حتماً انجام دهید)
```bash
python backtest.py BTCUSDT 90            # یک نماد، ۹۰ روز
python backtest.py ALL 90 --min-score 2  # همه‌ی نمادها
```
یا در تلگرام: `/backtest ALL 90`. گزارش شامل میانگین R خالص (بعد از کارمزد)، بیشترین افت، PF، درصد رسیدن به هر TP و یک قضاوت آماری است. قواعد را رعایت کنید: **پارامترها را روی همین داده بهینه نکنید**، بازه‌ی جدا برای تایید نگه دارید، و فقط اگر نتیجه در چند ماه و چند نماد مثبت و پایدار بود، بفروشید. روی داده‌ی تصادفی مصنوعی، استراتژی بعد از کارمزد ضرر می‌دهد (طبیعی است)؛ پس مثبت‌بودن روی داده‌ی واقعی باید از «ساختار بازار» بیاید، نه از شانس.

## تست‌ها (بدون اینترنت، بدون توکن، بدون پرداخت واقعی)
```bash
python -m unittest test_smc test_db test_bot test_backtest test_features -v
```
۱۱۵ تست: صرافی‌ها، BE، تنظیمات، کد هدیه، پیکربندی Railway، بک‌تست (صفحه‌بندی داده، کارمزد، افت، قضاوت آماری)، بکاپ و گزارش هفتگی، SMC (FVG، ساختار صعودی/نزولی و آینه‌ی آن، ترتیب SL/TP، عدم نگاه به آینده، داده‌ی خالی/ناقص/نامعتبر)، پرداخت (payload/مبلغ/ارز، تکراری، رقابت هم‌زمان، رول‌بک)، اشتراک، مهاجرت، ارسال، ردیابی، دسترسی ادمین. اگر `python-telegram-bot` یا `httpx` نصب نباشد، تست‌ها نسخه‌ی ساختگی جایگزین می‌کنند.

## محدودیت‌ها (صادقانه)
- تست‌ها با تلگرام و بایننس **ساختگی** انجام شده‌اند؛ رفتار واقعی (نمایش فاکتور، پرداخت واقعی Stars، دسترسی به API بایننس) باید با یک تست واقعی (مثلاً `PLANS=test:1:1`) بررسی شود.
- بک‌تست فقط روی داده‌ی مصنوعی انجام شده و **هیچ ادعای سودآوری ندارد**.
- وین‌ریت با TP دور (TP4/TP5) معمولاً پایین و نتایج نوسانی است.
- بایننس برخی مناطق (مثلاً آمریکا) را مسدود می‌کند؛ منطقه‌ی سرور را اروپا/آسیا انتخاب کنید یا `EXCHANGE_URL` را تغییر دهید.
- تریال رایگان با اکانت‌های متعدد قابل سوءاستفاده است؛ اگر لازم شد `TRIAL_DAYS=0` کنید.

## مشکلات رایج
| مشکل | راه‌حل |
|---|---|
| سیگنال نمی‌آید | طبیعی است؛ فقط ستاپ کامل ارسال می‌شود. `MIN_SCORE=1` سیگنال بیشتر می‌دهد. لاگ را برای `fetch ... failed` ببینید. |
| خطای ۴۵۱ بایننس | ریجن سرور را عوض کنید، یا `EXCHANGE=bybit`، یا `EXCHANGE_URL`. |
| اشتراک‌ها بعد از دیپلوی پاک شد | `DB_PATH` را روی Volume بگذارید. |
| `ConfigError` | پیام خطا دقیقاً می‌گوید کدام متغیر نادرست است. |
| `job_queue` خطا | `pip install "python-telegram-bot[job-queue]"` |
